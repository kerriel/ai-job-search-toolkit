# Contributing

This is a community toolkit. Contributions that help job seekers in more regions and on more platforms are welcome.

## Regional guides

The `examples/` folder contains regional guides for job boards and review sites. We'd love more.

**To add a guide for your region:**

1. Create a file in `examples/` named `<country-code>-job-boards.md` (for example `us-job-boards.md`, `de-job-boards.md`, `au-job-boards.md`)
2. Include:
   - The main job boards in your region, with URLs, what each is best for, and any notes on recruiter vs direct employer balance
   - Company review sites available in your region (such as Glassdoor, Kununu and Blind) with what to look for and known limitations
   - Any industry or seniority-specific guidance
3. Follow the format of [the UK job boards guide](examples/uk-job-boards.md).

## Job board search prompts

The job search prompt generator (`prompts/02-job-search.md`) writes self-contained search prompts for Cowork, the Claude Chrome extension or any AI assistant that can browse the web, with the user's profile written into them. It already supports LinkedIn, Indeed UK, and Totaljobs, and has an "Other" option for custom boards.

**To improve job board support:**

- If a supported board (LinkedIn, Indeed UK, Totaljobs) has changed its pages, buttons or menus, update the platform-specific instructions in the generator prompt
- If you want to add first-class support for a new board, add its navigation details alongside the existing platforms in the generator prompt
- Keep these unchanged (see [What not to change](#what-not-to-change)):
  - The screening order (posting date, working arrangement, industry, salary, seniority, role fit, employer vs recruiter)
  - The company review cross-referencing process
  - The two-tier dealbreaker system (hard dealbreakers filter out, strong preferences flag as "worth a closer look")

## General contributions

Bug reports, typo fixes, wording changes and accessibility fixes are all welcome. To report a problem or suggest an idea, open an issue: click the **Issues** tab on the toolkit's GitHub page, then **New issue**. To change the files yourself, open a pull request (PR), which proposes your change for review. If you're not sure how pull requests work, open an issue and describe the change in your own words.

## What not to change

Other files depend on these, so they need to stay the same:

- **The profile output format** (the structure of `my-profile.md` generated by the profile builder). All other prompts reference this format. Changing it would break every prompt that reads the profile.
- **The summary output format** in search prompts. This is designed to be pasted into your AI project for second-pass review.
- **The Rules section** of [the project instructions template](templates/project-instructions.md): Never guess, Profile maintenance, Memory maintenance and Consistency. They stop Claude inventing facts about you.

If you think something in these areas needs changing, open an issue to discuss it first.

## Submitting a PR

> [!CAUTION]
> A fork is public, and it stays public. Never save any personal information to it: no CV, no profile, no search prompts, no results, no name, no salary expectations, nothing about you.

1. On this repository's GitHub page, click **Fork** to make your own copy.
2. In your copy, create a branch with a name that says what you're changing, for example `add-us-regional-guide` or `fix-indeed-pagination`.
3. Make your changes.
4. Open a pull request with a clear description of what you're adding and why.

Keep each pull request to one regional guide or one job board prompt, because smaller changes are easier to review.
